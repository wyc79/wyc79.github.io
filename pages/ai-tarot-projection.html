What做了什么

For people who don’t believe in tarot but believe in thinking out loud. Three cards go face down on the table before anything is said. You are asked what you see in the one in front of you — not what it means, what you see — and it turns over when the conversation has somewhere to go.写给“不信塔罗、但信把话说出口”的人。开口之前，三张牌先扣在桌上。系统问你，眼前这张牌你看见了什么——不是它意味着什么，而是你看见了什么——等对话真有了去处，它才翻开。

Nothing here predicts anything. The deck is a projective surface: something specific and strange to point at, so the thing you actually wanted to say has an easier route out than “I’ve been a bit off lately.” The reader’s job is to hand your own words back to you in an order you hadn’t tried.这里没有任何预测。牌只是一块投射面：一个具体而古怪、可以拿来指认的东西，好让你真正想说的那句话，有一条比“我最近状态不太好”更好走的路。阅读者的职责，是把你自己的话按你没试过的顺序还给你。

It runs entirely in the browser against an API key you supply. No account, no server that remembers you, nothing of yours at rest anywhere but your own device.它完全运行在浏览器里，用你自己提供的 API 密钥。没有账号，没有会记住你的服务器，你的东西除了留在你自己的设备上，别处不会留存。

Main Achievements主要成果

  • Made privacy an architectural property rather than a policy: the key travels in one header, is used inside the single request that carried it, and is gone.
  • 把隐私做成架构属性，而不是一纸声明：密钥只在一个请求头里出现，在携带它的那一次请求中被使用，然后就没有了。
  • Wrote two relays — a ~300-line dependency-free Python one and a ~140-line Cloudflare Worker — against one contract, and made their indistinguishability a tested property instead of a claim.
  • 按同一份契约写了两个中继——一个约 300 行、零依赖的 Python 实现，一个约 140 行的 Cloudflare Worker——并把“二者不可分辨”做成被测试验证的性质，而不是一句声明。
  • Built a browser-side session engine in which an LLM makes three kinds of schema-constrained judgements: the opening, a per-turn flip gate that also grades stakes, and a narrative anchor.
  • 构建了一个浏览器端会话引擎，其中大模型做三类受 schema 约束的判断：开场、每轮的翻牌门控（同时给出风险等级），以及叙事锚点。
  • Kept the reading from turning into an interview by capping question depth at one step above where the person currently stands.
  • 把提问深度限制在“比对方当前所处位置高一级”，避免整场阅读变成一次审问式的问答。
  • Wrote a protocol scanner that checks transcripts against the reader’s own rules, and shared one definition of a violation between the tests, the seeded fixture, and the debug page.
  • 写了一个协议扫描器，按阅读者自己的规则检查对话记录，并让测试、固定种子样本与调试页共用同一份“何为违规”的定义。
  • Made the deck, the persona, and the few-shot examples plain data files with a schema validator, so changing how the reader sounds is a file save rather than a deploy.
  • 把牌组、人设与少样本示例都做成带 schema 校验的普通数据文件，于是改变阅读者的口吻只需保存文件，而不必重新部署。

What this is not.这不是什么。 A space for reflection, not therapy or crisis support. The app says so on its own first screen, and if a conversation goes somewhere the cards have no business being, the reader drops the tarot frame entirely, says so plainly, and points at real help — findahelpline.com lists people who can actually do something. 这是一个用来反思的空间，不是心理治疗，也不是危机干预。应用在自己的第一屏就写明了这一点；一旦对话走到牌不该插手的地方，阅读者会彻底放下塔罗这层外壳，把话直说，并指向真正的帮助——findahelpline.com 上列着真正能做点什么的人。

How如何实现

Privacy as architecture, not policy把隐私做成架构，而不是政策

The honest answer to “why should I trust this with my key” is that you shouldn’t have to trust it — you should be able to read it. So the whole path a key takes is short enough to read in one sitting, and there are three of them to choose from: straight to the provider with nothing of mine in between, where that provider’s CORS policy allows it; through a relay you run yourself, or through the hosted one for when you just want to open a URL on your phone.对“我凭什么把密钥交给它”这个问题，诚实的答案是：你本来就不该被要求信任它，你应该能把它读完。所以密钥所走的整条路径都短到可以一口气读完，而且有三条可选：直连服务商——中间没有任何属于我的东西，前提是该服务商的 CORS 策略允许；经过你自己运行的中继；或者经过托管的那一个——当你只想在手机上打开一个网址的时候。

Whichever path it takes, the rules are the same. The key arrives in an Authorization header, is used inside the single request that carried it, and then it is gone: never written to a session map, a global, a file, or a database. It is never logged — redacted by header name and by value, so a key that turns up inside an upstream error message is scrubbed before it reaches any output — and it is never echoed back in an error response. Neither relay knows what tarot is, holds session state, or keeps any of the conversation. Your transcripts live in your own browser storage and nowhere else.无论走哪条路，规则都一样。密钥在 Authorization 请求头里到达，在携带它的那一次请求中被使用，然后就没有了：不写进会话表、不写进全局变量、不写进文件、不写进数据库。它绝不被记录——按请求头的名字和它的值双重脱敏，因此即便某个密钥出现在上游的报错信息里，也会在抵达任何输出之前被擦掉——也绝不会被回显在错误响应中。两个中继都不知道塔罗是什么，不持有会话状态，也不保留任何对话内容。你的对话记录只存在于你自己的浏览器里。

Two relays, one contract — and a test that says so两个中继，一份契约——并由测试来说话

Self-hosting gets a ~300-line Python relay with no dependencies outside the standard library; the hosted path gets a ~140-line Cloudflare Worker. Both implement the same contract, written down in RELAY.md, and the frontend cannot tell which one is answering. That indistinguishability is a design rule, so it is tested rather than asserted: one contract suite of twenty tests runs against both relays and requires them to agree on every branch — including a health response that does not give away which implementation you reached.自托管用的是一个约 300 行、除标准库外零依赖的 Python 中继；托管路径用的是一个约 140 行的 Cloudflare Worker。两者实现同一份契约（写在 RELAY.md 里），前端无法分辨究竟是谁在应答。这种“不可分辨”是一条设计规则，所以它被测试，而不是被声称：一套二十个用例的契约测试对两个中继各跑一遍，要求它们在每条分支上都一致——包括那个不泄露你连到了哪个实现的健康检查响应。

The same suite sends a canary key down every path, error paths included, and fails if that string appears anywhere in the captured output. The two relays differ in exactly one way, deliberately: the Python one has a dev-log flag, off by default, for a person logging their own conversations on their own machine. The Worker has no logging code path at all — not a disabled one, not a commented-out one — and a test greps its source to keep it that way.同一套测试还会把一个“金丝雀”密钥送进每一条路径（包括每一条出错路径），只要这个字符串出现在捕获到的任何输出里，测试就失败。两个中继只有一处刻意的不同：Python 那个带有默认关闭的调试日志开关，供人在自己的机器上记录自己的对话。Worker 则完全没有日志代码路径——不是被关掉的，也不是被注释掉的——并有一个测试去 grep 它的源码，好让它保持如此。

The key’s whole life. It is typed into the settings panel and held in memory for the tab — written to the device only if you tick “remember on this device” — then travels in one Authorization header to whichever relay is configured. Inside either one it is used once and dropped, never stored, never logged, never echoed. Past readings stay in your own browser storage; no relay holds any of them. The band along the bottom is what keeps the middle column honest: twenty contract tests against both implementations, a canary key that must appear in no captured output on any branch, and a grep over the Worker source for logging code.密钥的一生。它被输入设置面板、只在当前标签页的内存中保存——只有当你勾选“在本设备上记住”时才会写入设备——随后在一个 Authorization 请求头里发往所配置的那个中继。在任一中继内部，它被使用一次即丢弃：不存储、不记录、不回显。既往的对话记录留在你自己的浏览器存储里，任何中继都不持有。底部那条带子，正是让中间那一栏站得住脚的东西：二十个契约测试同时验证两个实现，一个“金丝雀”密钥在任何分支的输出里都不得出现，以及一次对 Worker 源码中日志代码的 grep。

A conversation engine that judges before it speaks先判断，再开口的对话引擎

The session engine runs in the browser, and an LLM makes three kinds of decisions inside it, each constrained to a schema rather than left to prose. The opening reads the first thing you say: did you actually name something to look at, and is a tarot frame the wrong thing to hand this person. The flip gate runs on every turn and decides whether a card has earned its turn — how much you disclosed, whether the answer was about your life or about the picture, whether it was hedged, and what the stakes are. Stakes have a crisis level, and it is the one that drops the frame: no cards, no imagery, no closing ritual.会话引擎跑在浏览器里，大模型在其中做三类决策，每一类都受 schema 约束，而不是任其自由发挥。开场判断你说的第一句话：你有没有真的指出一个想看的东西，以及塔罗这层外壳是不是根本不该递给这个人。翻牌门控每轮都跑，决定某张牌是否已经被“挣到”：你透露了多少、这个回答讲的是你的生活还是画面本身、是否留了退路，以及风险有多高。风险等级里有一档是危机，正是它会让整个外壳被放下：不再有牌、不再有意象、不再有收尾的仪式。

The third is the anchor, committed once after the first card: what this reading is actually about, in your register rather than as a diagnosis. An anchor phrased as a verdict is the failure mode — every question after it steers toward confirming the sentence the anchor already wrote — so a beat that asserts a finding is sent back to the judge once for an open question instead. The cost of being wrong about that is one extra call, which is cheap next to spending two more cards proving something you never said.第三类是锚点，在第一张牌之后确定一次：这场阅读究竟是关于什么的，用你的语气说出来，而不是给出一份诊断。锚点最典型的失效方式，是把它写成一个结论——此后的每个问题都会朝着印证这句话的方向走——所以，一旦某个锚点断言了某个“发现”，它会被退回给判断模型一次，改成一个敞开的问题。判断错的代价不过是多一次调用，比起用剩下两张牌去证明一句你根本没说过的话，这很便宜。

Questions climb a ladder — what it is, what happened next, what it is like for you, why it matters to you, what you will do — and a question may stand at most one rung above the answer before it. That cap is what keeps a reading from turning into an interview. A protocol scanner runs rule checks over a finished transcript and reports where the reader broke its own rules; the tests, the seeded fixture, and the debug page all call the same scanner, so there is one definition of a violation rather than three that can drift apart.提问沿着一架梯子往上走——它是什么、后来发生了什么、这对你来说是什么滋味、它为什么对你重要、你会怎么做——而一个问题最多只能比上一个回答高出一级。正是这条上限，让一场阅读不至于变成审问。协议扫描器会对完成的对话记录跑规则检查，指出阅读者在哪里违反了自己的规矩；测试、固定种子样本和调试页调用的是同一个扫描器，因此“何为违规”只有一个定义，而不是三个会各自漂移的定义。

Bring your own deck用你自己的牌

If you own a tarot deck, the app would rather you used it. Choose “my own deck” before you start and it deals empty slots instead of cards: you shuffle, lay them face down yourself, and turn one over by hand when the reading reaches it. It then asks which card you turned, and you tell it. The only thing that crosses the wire is the card’s name. It is the better version of the idea, because the object on the table is genuinely yours and genuinely random, and because the small ceremony of turning a card over by hand is most of what the interface was imitating in the first place.如果你手上有一副塔罗牌，这个应用更希望你用它。开始前选择“用我自己的牌”，它发下的就不是牌，而是空位：你自己洗牌、自己把牌扣在桌上，等阅读进行到那一张时，由你亲手翻开。然后它问你翻到的是哪张，你告诉它。跨越网络的只有牌名。这是这个想法更好的版本，因为桌上那个东西真正属于你、也真正随机，而且亲手翻牌那点小小的仪式感，本就是这个界面一直在模仿的大部分内容。

Forkable symbol packs可分叉的符号包

Tarot is one symbol pack on top of a generic reflection engine, and a pack is just a directory: the cards and their per-position meanings, the persona that says how the reader talks, the few-shot examples of what good looks like, and the images. All of them are static files the frontend fetches, which is the point — changing how the reader sounds is a file save, never a redeploy. A validator checks any pack directory against the schema, not just the one that ships, because “fork it, drop in your own deck” only means anything if a fork can check itself.塔罗只是叠在一个通用反思引擎之上的一个符号包，而一个包不过是一个目录：牌、每个牌位下的释义、规定阅读者如何说话的人设、示范“好长什么样”的少样本示例，以及图片。它们全都是前端直接获取的静态文件——这正是关键：改变阅读者的口吻只需保存文件，从不需要重新部署。校验脚本可以对任意一个包目录做 schema 检查，而不只是随仓库附带的那一个；毕竟“分叉它，换上你自己的牌”这句话，只有在分叉能自检时才算数。

The pack browser, which needs no key at all and so is the cheapest way to confirm a relay is up: the green line is a live health check naming the providers it can reach. Below it, one card as the engine sees it — an imagery line, a reader-only description of what is literally in the picture, and a separate meaning per position (situation, obstacle, advice). All of it is text in a data file, editable without touching a line of code.符号包浏览器。它完全不需要密钥，因此是确认中继是否在线的最省事的办法：绿色那行是实时的健康检查，列出它能连到的服务商。下方是引擎眼中的一张牌——一句意象描述、一段仅供阅读者使用的“画面上究竟有什么”，以及每个牌位（处境、阻碍、建议）各自的释义。这些全都是数据文件里的文本，不碰一行代码就能修改。
