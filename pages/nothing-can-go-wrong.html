What做了什么

Nothing Can Go Wrong is a game jam project about indirect control and planning around consequences. Instead of steering the character moment by moment, players plot a route, set it in motion, and watch the plan succeed or unravel as the environment reacts. Nothing Can Go Wrong 是一款围绕间接操控和预判后果展开的 Game Jam 游戏。玩家并不实时控制角色，而是先规划路线、再启动行动，看计划如何在场景机关的影响下顺利完成或意外失控。

I served as the primary programmer, building the route-planning tools, game-state logic, environmental interactions, and player feedback while integrating assets created by teammates. 我担任主程序，负责路线规划工具、游戏状态逻辑、场景互动和玩家反馈，并将队友制作的素材整合进游戏。

The challenge was to keep each interaction predictable on its own while allowing trains, whirlpools, spring pads, trapdoors, and other hazards to combine into surprising chain reactions. 设计难点在于让火车轨道、漩涡、弹跳板、活板门等机关各自遵循清晰规则，同时又能彼此组合，制造出出人意料的连锁反应。

Main Achievements主要成果

  • Implemented route planning and autonomous playback, turning a player-authored path into a complete run.
  • 实现路线规划与自动执行系统，把玩家画出的路径转化为一段完整行动。
  • Built reusable environmental interactions for tracks, whirlpools, spring pads, trapdoors, and chain reactions.
  • 为轨道、漩涡、弹跳板、活板门和连锁反应搭建可复用的场景互动。
  • Integrated UI, input, feedback animation, and teammate-created art into a readable, cohesive experience.
  • 将 UI、输入、反馈动画和队友制作的美术资源整合成清晰一致的体验。
  • Delivered a polished playable build within the jam deadline; the project ranked in the top 20% overall.
  • 在 Game Jam 截止前交付了完成度较高的可玩版本，最终总排名进入前 20%。

How如何实现

Building the Planning Loop搭建规划与执行循环

Because of the short jam timeline, the engineering goal was to make every environmental effect easy to tune and combine. The route planner, game state, and reactive objects were kept separate so the team could add hazards without rewriting the core loop. 由于 Game Jam 时间紧张，我把工程重点放在可调、可组合的场景效果上。路线规划、游戏状态和互动机关彼此分离，因此团队加入新障碍时不必重写核心循环。

  • Implemented the route-drawing and execution loop in Godot and GDScript.
  • 使用 Godot 和 GDScript 实现路线绘制与自动执行循环。
  • Connected input, game state, collision responses, and feedback animation so cause and effect stayed legible.
  • 串联输入、游戏状态、碰撞响应和反馈动画，让玩家能看懂每个结果是如何发生的。
  • Exposed movement speed, impulse strength, and trigger timing for quick tuning during playtests.
  • 开放移动速度、冲量强度和触发时序等参数，便于在玩法测试中快速调校。

Rapid Iteration and Debugging快速迭代与调试

Frequent playtests exposed where surprise became confusion. We tightened interaction rules, strengthened feedback animation, and repeatedly adjusted timing and force values while keeping a stable build available to the team. 频繁的玩法测试帮助我们判断：哪些意外结果有趣，哪些只会让人困惑。我们因此收紧互动规则、强化反馈动画，并反复调整时序和力度参数，同时始终为团队保留稳定可玩的版本。

  • Used short test-tune-test loops to refine timing, readability, and difficulty.
  • 通过短周期的“测试—调参—再测试”循环打磨时序、可读性和难度。
  • Debugged interaction order and edge cases in multi-object chain reactions.
  • 排查多个场景物体连锁反应中的触发顺序与边界情况。
  • Kept the playable build stable while mechanics and art were changing rapidly.
  • 在机制和美术资源快速变化的同时，持续维护可玩版本的稳定性。
